# CrossBorder Ops Agent · 交付说明

版本：0.2.0
交付形态：本地部署（源码或容器），数据落在客户自己的服务器上

---

## 一、这套系统解决什么问题

跨境运营的日常不是"不知道要做什么"，而是**判断没有统一口径**：

- 同一个类目，老运营看价格带供需比就知道能不能进，新人只能跟着看谁卖得最好；
- 广告亏钱时，有人先降价、有人先改图、有人直接关掉，三种动作对应三种后果，但没人算过盈亏线；
- 差评多了就说"要改产品"，其实大部分差评改一段文案就能消掉，剩下才是工厂的事。

本系统把老运营的判断规则固化成可计算的流程，并且要求每一次判断都能指回具体数字。七个环节覆盖"选品 → 定价 → 素材 → 投放 → 复盘"，所有指标由确定性脚本计算，模型只负责解读与措辞。

## 四、验收步骤（约 15 分钟）

按顺序执行，每步都有明确的通过标准。

### 第 1 步 · 环境自检

```bash
python scripts/preflight.py
```

**通过标准**：Python 版本、依赖、目录权限、数据库四项为 `[OK]`。
上线前还要求"强制登录"为 `[OK]`（见部署手册第四节）。

### 第 2 步 · 启动服务

Windows 双击 `start.bat`，或命令行：

```bash
python run.py
```

**通过标准**：终端出现 `Uvicorn running on http://127.0.0.1:8000`，浏览器可打开首页。

### 第 3 步 · 跑一次完整诊断

页面上点击"运行全链路"（或命令行 `python scripts/demo_run.py`）。

**通过标准**：

| 检查项 | 期望值 |
|---|---|
| 七个环节状态 | 全部 `ok`，无 `blocked` |
| 动作总数 | 28 条左右 |
| P0 动作 | 8 条左右 |
| 回流 | 3 条（广告→文案、评论→文案、评论→主图） |
| 耗时 | 小于 1 秒 |

### 第 4 步 · 验证闭环

```bash
python scripts/demo_cycle.py
```

**通过标准**：三轮分别输出"首次运行 / 改善 / 恶化"，第二轮能看到 ROAS 上升与 P0 组数下降。

> 注意：该脚本会清空运行历史，加 `--keep` 可保留。

### 第 5 步 · 验证权限与隔离

页面右上角初始化负责人账号 → 新建一个"只读"成员 → 用只读账号登录。

**通过标准**：

- 只读账号看不到"运行"按钮，访问 `/api/runs` 写操作返回 403
- 修改"CTR 基准"被拒绝，提示需要负责人权限
- 新建第二个店铺后，两个店铺的运行记录互不可见

### 第 6 步 · 备份可恢复

```bash
python scripts/backup_db.py
python scripts/backup_db.py --list
```

**通过标准**：`data/backups/` 下出现 `app-时间戳.db`，大小与 `data/app.db` 接近。

## 五、系统边界

明确说明"不做什么"，避免验收时产生预期偏差。

### 会做

- 基于你导出的类目 / 广告 / 评论数据，给出可追溯的诊断结论与动作清单
- 每条动作附带验证方式（几天后看哪个指标）
- 同一份数据重复运行，结论逐字一致
- 跨运行对比：上次的动作有没有让指标变好
- 按店铺、按角色隔离数据与权限

### 不会做

| 不做 | 原因 |
|---|---|
| 不操作卖家后台 | 不改价、不停广告、不改预算；动作清单交人审批 |
| 不采集数据 | 类目/广告/评论由使用者导出提供，系统不做爬虫 |
| 不出图不出片 | 产出九宫格规划与出图 Prompt，渲染交给生图/剪辑工具 |
| 不判断因果 | 只指出"指标变了"，不宣称"因为你的改动" |
| 不替代平台规则 | 费率、标题上限、图片规格是快照，发布前需人工复核 |

### 已知限制

| 限制 | 影响 | 缓解 |
|---|---|---|
| 调度器按单进程设计 | 多副本部署会重复触发定时任务 | 只保留一个实例，或设 `ECOM_SCHEDULER=off` |
| 会话存在服务端单表 | 无 Redis，多实例需共享会话存储 | 单实例部署 |
| 平台预设为经验值 | 费率与 CTR 基准可能与你的账号有偏差 | 上线后用自己账号数据校准阈值 |
| 评论归因在 65 条差评上评估 | 真实评论更口语化，准确率会低于演示值 | 低置信度样本标记"待人工确认"，不生成动作 |
| 时间轴假设按天粒度 | 按周/月汇总的数据，"近 7 天"会变成"最近 7 行" | 导入前确认导出粒度 |
| 日序判断依赖证据 | 整列都是 01~12 写法时按平台习惯推断 | 界面会显示假设与警告，请核对 |

## 六、数据与安全

- 所有数据存放在客户自己的服务器 `data/` 目录，不上传任何第三方
- 接大模型时，只有**创意类文本**（标题、口播稿）会发送给模型服务商；定价、广告分级、评论归因全部本地计算
- 不配置大模型时，系统以"离线规则模式"运行，功能完整
- 密码使用 PBKDF2-HMAC-SHA256（10 万次迭代 + 随机盐）存储
- 上传文件大小上限 10 MB、行数上限 5 万行

## 七、交付后需要客户确认的三件事

1. **初始化负责人账号**（首次打开页面时完成），并设置 `ECOM_REQUIRE_LOGIN=1`
2. **确认部署方式**：源码 + 虚拟环境，或 Docker（见部署手册）
3. **确认是否清除演示数据**：`python scripts/reset_data.py --yes`
