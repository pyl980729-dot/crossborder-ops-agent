# 部署手册

适用于把系统部署到客户自己的服务器。两种方式任选其一，**不要同时用两种方式指向同一个 `data/` 目录**。

---

## 一、部署前检查

| 检查项 | 命令 | 期望 |
|---|---|---|
| Python | `python -V` | 3.10 以上 |
| 端口 | `netstat -ano \| findstr :8000` | 8000 未被占用 |
| 磁盘 | `df -h`（Windows 看磁盘属性） | 至少 1 GB 可用 |
| 目录权限 | 对 `data/` 有写权限 | 需要建库、写日志、存上传文件 |

---

## 二、方式 A：源码 + 虚拟环境（推荐）

### 1. 放置代码

```bash
# Linux
sudo mkdir -p /opt/crossborder && sudo chown $USER /opt/crossborder
# 把交付包解压到 /opt/crossborder
```

### 2. 首次启动

Windows 直接双击 `start.bat`。Linux / macOS：

```bash
cd /opt/crossborder
chmod +x start.sh
./start.sh
```

脚本会自动完成：建虚拟环境 → 装依赖 → 缺种子数据时生成 → 启动服务。

### 3. 验证

```bash
curl http://127.0.0.1:8000/api/health
```

应返回 `{"status":"ok",...}`。浏览器打开 `http://服务器IP:8000` 应看到界面。

### 4. 配置生产环境

```bash
cp .env.production.example .env
```

至少填写两项：

```ini
ECOM_REQUIRE_LOGIN=1
ECOM_CORS_ORIGINS=https://ops.your-domain.com
```

> `ECOM_REQUIRE_LOGIN=1` 是硬性要求。不开的话，任何能访问 8000 端口的人都会被当成负责人。

### 5. 初始化负责人账号

重启服务后打开页面，会看到"初始化"表单：

- 用户名：至少 2 位
- 密码：至少 6 位（生产建议 12 位以上，含大小写与数字）
- 显示名：可留空，默认同用户名

创建的第一个账号就是**负责人（owner）**，拥有全部权限。之后系统强制登录，`/api` 全部要求会话或服务令牌。

### 6. 常驻运行（systemd）

```ini
# /etc/systemd/system/crossborder.service
[Unit]
Description=CrossBorder Ops Agent
After=network.target

[Service]
Type=simple
User=ecom
WorkingDirectory=/opt/crossborder
EnvironmentFile=-/opt/crossborder/.env
ExecStart=/opt/crossborder/.venv/bin/python run.py --host 127.0.0.1 --port 8000
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now crossborder
sudo systemctl status crossborder
```

注意 `--host 127.0.0.1`：只监听本机，由 Nginx 对外。不要直接 `0.0.0.0` 暴露到公网。

## 三、方式 B：Docker

### 1. 准备配置

```bash
cp .env.production.example .env
# 编辑 .env：ECOM_REQUIRE_LOGIN=1、ECOM_CORS_ORIGINS
```

### 2. 启动

```bash
docker compose up -d --build
docker compose logs -f app
```

### 3. 验证

```bash
curl http://127.0.0.1:8000/api/health
docker compose ps          # STATUS 应为 healthy
```

### 4. 数据持久化

`docker-compose.yml` 已把 `./data` 挂到容器 `/app/data`，数据库、日志、上传文件都在宿主机上，删容器不丢数据。

### 5. 更新配置

改完 `.env` 后：

```bash
docker compose up -d
```

容器会自动重建并读取新变量。

### 6. 不要做的事

- 不要 `deploy.replicas > 1`：内置调度器按单进程设计，多副本会重复触发定时任务
- 不要在容器里改代码：改完重建镜像

## 四、反向代理与 HTTPS

以 Nginx 为例：

```nginx
server {
    listen 80;
    server_name ops.your-domain.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name ops.your-domain.com;

    ssl_certificate     /etc/ssl/certs/ops.crt;
    ssl_certificate_key /etc/ssl/private/ops.key;

    # 上传上限 10MB，这里留余量
    client_max_body_size 12m;

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
}
```

要点：

- `client_max_body_size` 必须 ≥ 12m，否则上传 CSV 会被 Nginx 先拦掉（返回 413）
- 会话 Cookie 是 `HttpOnly + SameSite=Lax`，HTTPS 下正常工作
- 若前后端不同域，必须把前端域名填进 `ECOM_CORS_ORIGINS`

## 五、配置项

| 变量 | 默认 | 说明 |
|---|---|---|
| `ECOM_REQUIRE_LOGIN` | 关闭 | 设为 `1` 强制登录。**对外必开** |
| `ECOM_API_TOKEN` | 空 | 服务令牌，脚本/监控用。设了之后可用 `X-API-Token` 调用 |
| `ECOM_CORS_ORIGINS` | `*` | 允许的跨域来源，逗号分隔。**生产必须收紧** |
| `ECOM_LOG_LEVEL` | `INFO` | `DEBUG` / `INFO` / `WARNING` |
| `ECOM_SCHEDULER` | `on` | 设为 `off` 关闭内置调度器 |
| `ECOM_LLM_PROVIDER` | `rule` | `rule` 离线 / `dashscope` / `deepseek` / `openai` |
| `DASHSCOPE_API_KEY` 等 | 空 | 对应服务商的密钥 |
| `ECOM_LLM_MODEL` | `qwen-plus` | 模型名 |
| `ECOM_LLM_BASE_URL` | 空 | 自建兼容端点时使用 |

改完配置必须重启服务（`python run.py` 或 `docker compose up -d`）。

## 六、备份与恢复

### 备份

```bash
python scripts/backup_db.py --keep 14
```

- 输出到 `data/backups/app-YYYYmmdd-HHMMSS.db`
- 使用 SQLite 在线备份接口，**服务运行中也能安全备份**
- `--keep 14` 只保留最近 14 份

定时备份（Linux crontab）：

```cron
0 3 * * * cd /opt/crossborder && .venv/bin/python scripts/backup_db.py --keep 14 >> data/logs/backup.log 2>&1
```

还需要单独备份 `data/uploads/`（上传的原始数据集），它与数据库分开存放。

### 恢复

```bash
# 1. 停服务
sudo systemctl stop crossborder

# 2. 备份当前库（以防万一）
mv data/app.db data/app.db.bak

# 3. 还原
cp data/backups/app-20261116-030000.db data/app.db

# 4. 启动
sudo systemctl start crossborder
```

恢复后建议跑一次 `python scripts/preflight.py` 确认库完整性。

## 七、升级与回滚

### 升级

```bash
# 1. 备份
python scripts/backup_db.py

# 2. 停止服务
sudo systemctl stop crossborder

# 3. 替换代码（保留 data/ 与 .env）
# 4. 更新依赖
.venv/bin/python -m pip install -r requirements.txt

# 5. 数据库自动迁移
#    服务启动时 init_db() 会补新增列，老库无需手工改

# 6. 启动 + 验证
sudo systemctl start crossborder
curl http://127.0.0.1:8000/api/health
```

### 回滚

代码回滚到上一版本目录，数据库用升级前的备份覆盖。数据库迁移是"只加列不删列"，旧版本读新库通常没问题，但**不要依赖这一点**，回滚时一并恢复数据库最稳。

## 八、部署后的第一件事

```bash
python scripts/preflight.py
```

全部 `[OK]` 或只有可接受的 `[WARN]` 才算部署完成。特别关注：

- `强制登录` 必须是 `[OK]`
- `跨域来源` 不能是"允许所有来源"
- `端口 8000` 不应被占用（重复启动会失败）
