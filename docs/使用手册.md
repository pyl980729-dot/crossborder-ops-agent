# 使用手册（运营视角）

这份文档面向日常使用者，不涉及安装与运维。目标是让你在半小时内知道：**每个页面在说什么、该看哪一行、看完该做什么。**

---

## 一、第一次进入

打开系统后，有两种情况：

| 看到什么 | 说明 | 该怎么做 |
|---|---|---|
| 初始化表单 | 系统里还没有账号 | 填写用户名 / 密码 / 显示名，创建负责人账号 |
| 登录表单 | 已有账号 | 输入账号密码；有多个店铺时可选择进入哪个 |

第一个创建的账号是**负责人**，拥有全部权限。之后可以在「成员」页添加运营和只读账号。

---

## 二、五分钟跑通一次诊断

不用准备任何数据，系统自带演示数据（一个巴西站的电动滑板车类目）。

1. 打开首页 → 点「运行全链路」
2. 等 1 秒左右，七个环节依次亮起
3. 从上往下读每个环节的**头条**（一行结论）
4. 展开任意环节，看「解读」和「动作」
5. 滑到底部看「回流」：广告和评论把问题指回了文案与主图

跑完之后，运行记录会留存在「历史」里，下次运行会自动和这次对比。

> 想清空演示数据、从自己的数据开始：`python scripts/reset_data.py --yes`

## 三、七个环节怎么读

### 01 市场调研 —— 这个类目该不该进

| 看什么 | 怎么判断 |
|---|---|
| 类目容量 | 月销量与 GMV。低于你所在平台的经验线，起量会很慢 |
| 集中度 CR3 / CR10 | 高度集中 = 头部吃掉大部分销量，别正面硬刚；分散 = 容易滑向价格战 |
| 价格带机会指数 | 销量份额 ÷ 商品数份额。大于 1.2 是供不应求，小于 0.8 是供给过剩 |
| 进入评分 | 四项信号（集中度、机会价位、口碑缺口、容量）合计 4 分，达到门槛才建议进 |

结尾那句「可进 / 谨慎进 / 不建议进」是自动收敛的结论，下面会列出依据。

### 02 选品与定价 —— 卖一件能赚多少

重点是三个数：

- **净利率**：扣掉佣金、税费、退货、成本、物流之后真正剩下的比例
- **盈亏线 ROAS**：广告花到这个数就白干。**后面所有广告判断都以它为准**
- **可承受 CPC**：每点击一次的期望贡献，超过这个价买流量就是亏

如果系统说「当前售价比达标线高 X%」，**不要直接降价**——这段空间是优惠券和大促的弹药，直接降价会把价格锚点打穿。

### 03 Listing 文案 —— 标题能不能被搜到

| 看什么 | 怎么判断 |
|---|---|
| 字符数 / 上限 | 用满但别超。超了会被截断或拒收 |
| 前置权重区 | 前 N 个字符里有没有核心词。手机端只显示前面那一小段 |
| 关键词覆盖 | 没进标题的词应该下沉到后台 search terms，不要硬塞 |
| 堆砌检测 | 同一个词出现 3 次以上直接判不通过 |

系统会给三个变体（搜索导向 / 转化导向 / 人群导向），选一个上架，7 天后看曝光差异。

### 04 主图与详情图 —— 九张图各解决什么疑虑

九宫格是固定顺序，不是随便九张：

```
主图（点进来）→ 卖点图（相信）→ 场景（对号入座）→ 参数（比得清）
→ 细节（做工）→ 尺寸（合不合适）→ 包装清单（不缺件）→ 使用步骤（不会用错）
```

每一格都给出图 Prompt 和合规要求。**包装清单图和使用步骤图优先做**——它们对应的是「改图就能消掉」的差评。

### 05 短视频脚本 —— 25 秒怎么讲清一件事

四段结构：Hook（0-3s）→ 痛点（3-8s）→ 证明（8-20s）→ CTA（20-25s）。

只看两个数：

- **口播所需时长 vs 分镜总时长**：超了要删词
- **空档比例**：口播只占一半时长，中间要靠画面填，否则完播率会掉

Hook 只讲一个卖点。前 3 秒讲两个等于一个都没讲进去。

### 06 广告诊断 —— 哪条在失血

这是最该每天看的一页。分级规则：

| 级别 | 含义 | 该做什么 |
|---|---|---|
| **P0** | 每出一单都在倒贴现金 | 当天降预算 30%-50%、降出价 15%；3 天后没回到盈亏线就关停 |
| **P1** | 亏但可控，或创意/落地页有问题 | 先改创意或详情页，7 天后再决定是否动出价 |
| **P2** | 已达目标 ROAS | 每次加 20% 预算，观察 3 天 |
| **HOLD** | 曝光不够或没花钱 | 不动，样本不足时任何结论都是噪声 |

判定顺序是固定的：曝光够不够 → 有没有花钱 → CTR 是否达标（创意问题）→ 有点击没订单（落地页问题）→ 最后才看 ROAS。

**为什么顺序重要**：一个 CTR 只有 0.8% 的组，如果只看 ROAS 会被判成"出价太高"，而你降出价，CTR 只会更低。

### 07 评论归因 —— 差评里哪些改文案就能消掉

八类归因里，五类属于「内容可修复」：误解型、参数不符合预期、配件缺失、使用困难、描述不符。

**可修复率**是这一页最值钱的数字：它把"差评太多"翻译成"其中 81% 改文案/补图就能消掉，剩下 19% 才是工厂的事"。

机器分不出来的会标「待人工确认」，不计入占比、不生成动作——猜错分类比不分类更糟，它会让你去改一个不存在的问题。

## 四、接自己的数据

### 支持的三类 CSV

| 类型 | 必填列 | 常见可选列 |
|---|---|---|
| 类目商品（products） | 售价、月销量 | SKU、标题、品牌、评分、评论数、配置、是否新卖家 |
| 广告（ads） | 广告组、曝光、点击、花费、订单、销售额 | 日期 |
| 评论（reviews） | 评分 | 日期、内容、归因、是否带图 |

列名不用改。系统会做中英别名匹配，这些写法都认：

```
曝光量 / 曝光 / 展示次数 / impressions
花费(BRL) / 消耗 / spend / cost
广告组 / 广告名称 / campaign
销售额 / GMV / 成交金额 / revenue
```

### 上传会做什么

1. 猜编码：UTF-8 / GBK / GB18030 依次尝试（中文 Excel 导出常是 GBK）
2. 模糊匹配列名：去空格、去括号、大小写不敏感
3. 解析脏数字：`R$ 420,50`、`1.234,56`、`1,234.56` 都能正确识别
4. 归一日期：`2026-11-07`、`07/11/2026`、`7 de novembro de 2026`、`20261107`

### 上传后看三件事

| 返回字段 | 含义 |
|---|---|
| `mapping` | 每个字段匹配到了哪一列；对不上就是这里的问题 |
| `ignored_columns` | 被忽略的列（通常是平台自带的无关字段） |
| `skipped` + `warnings` | 跳过的行数和原因。**逐行看 warnings**，多半是某列混了非数字或含逗号未加引号 |

### 常见报错怎么处理

| 报错 | 原因 | 解决 |
|---|---|---|
| 缺少必填列：X | 列名没匹配上 | 看返回的「当前表头」，手动把列名改成上面的别名 |
| 第 N 行某列不是数字 | 该行有合并单元格 / 备注文字 | 删掉该行或清空该格 |
| 字段数多于表头 | 某列内容含逗号却没加引号 | 用 Excel 重新导出，或给该列加引号 |
| 日期无法识别 | 格式超出支持的写法 | 统一改成 `YYYY-MM-DD` |

### 日期列很关键

有日期才能做「近 7 天 vs 前 7 天」对比。没有日期，系统只能回答"这堆数据整体怎么样"，看不出趋势。

如果日期格式是 `01/11` 这种两段都不超过 12 的写法，系统会：
1. 先在整列找证据（有没有 25/10 这种大于 12 的日子）
2. 找不到就按店铺平台的惯例推断（巴西/欧洲按日/月，Amazon 按月/日）
3. 把假设和警告一起显示出来

**看到"已按日/月解析"的警告时，请核对源文件**——猜错会让趋势图整体错位。

## 五、调阈值

「阈值」页有 24 个参数，按分组排列。每个值都能看到来源：

```
请求参数 > 界面设置 > 平台预设 > 系统默认
```

### 什么时候需要调

| 情况 | 调哪个 |
|---|---|
| 你的平台 CTR 普遍不是 2% | 广告诊断 → CTR 基准 |
| 广告数据量小，7 天波动大 | 时间轴 → 广告对比窗口（改 14） |
| 评论很少，按月对比样本不够 | 时间轴 → 评论对比窗口（改 42 或 60） |
| 类目集中度普遍很高 | 市场调研 → 高度集中线（CR3） |
| 你能接受更低的净利率 | 选品定价 → 目标净利率 |

### 调完怎么验证生效

**看"诊断原因"，不要看"诊断数量"。**

举个例子：把 CTR 基准从 2.5% 调到 0.5%，P1 组数可能一个都没变，但结论从「CTR 不达标（改图）」变成了「ROAS 未达标（调出价）」——这才是真正生效的证据。

### 权限说明

- 广告诊断、市场调研、选品定价这三组会**改变谁被判失败**，只有负责人能改
- 评论归因、Listing、短视频只影响产出形态，运营可以改
- 填超出范围的值会被拒绝并提示

## 六、看闭环：上次的动作有没有用

每次运行结束，系统会自动和上一次对比，产出三样东西：

### 1. 指标对比

```
广告整体 ROAS    5.00 → 8.06   ↑ 改善
P0 失血组         2 → 0        ↑ 改善
```

每个指标都声明了方向（越大越好 / 越小越好），只在方向一致时才算改善。

### 2. 遗留动作

```
上次的 9 条 P0 里：3 条已消除，6 条仍在
```

**"仍在"就是在说：动作没执行，或者执行了没生效。** 这是闭环最硬的价值——系统不评价你，只如实告诉你。

### 3. 整体判定

改善 / 恶化 / 持平，依据是"改善项数 vs 恶化项数"，不加权。

### 注意

- 系统不判断因果。ROAS 涨了可能是季节性、可能是竞品下架，它只指出"变了"
- 「可修复率下降」不一定是坏事：误解型差评修完了，剩下的自然都是不可修复类。所以闭环判定用的是**差评率**，不是可修复率

## 七、定时任务

「自动化」页可以建定时任务，让系统每天自动跑一次：

```
0 9 * * *      每天 09:00
0 9 * * 1      每周一 09:00
*/30 * * * *   每 30 分钟
```

操作：

1. 填任务名和 cron（页面会显示"每天 09:00"这类中文描述，确认没写错）
2. 选数据来源
3. 建完点「立即执行一次」验证配置
4. 到点后自动跑，运行记录里触发方式标为 `scheduler`

两个行为要知道：

- 服务停了两天后重启，**只会补跑一次**，不会把错过的十几次全补上
- 定时任务只跑诊断，不会自动改价或停广告

## 八、成员与权限

| 能做什么 | 负责人 | 运营 | 只读 |
|---|---|---|---|
| 看运行记录与报告 | 是 | 是 | 是 |
| 跑诊断、传数据 | 是 | 是 | 否 |
| 改内容类阈值（词频上限、语速） | 是 | 是 | 否 |
| 改核心阈值（CTR 基准、集中度线） | 是 | 否 | 否 |
| 删数据、管成员、审批 P0 | 是 | 否 | 否 |

多店铺之间数据完全隔离：A 店的阈值、运行记录、定时任务不会影响 B 店，A 店的运行也不会成为 B 店的对比基线。

## 九、常见问题

**Q：接了模型和不接模型，结论会变吗？**
不会。定价、广告分级、评论归因永远走确定性脚本。模型只改写标题和口播稿这类创意内容。同一份数据跑两次，结论逐字一致。

**Q：为什么有的环节显示"已停止计算"？**
缺必填字段。系统不会猜数据，会明确告诉你缺哪一个。补齐后重跑即可。

**Q：能自动改价 / 自动停广告吗？**
不能，这是刻意的设计。真正的运营动作需要人判断上下文（预算周期、库存、大促节奏），自动执行一次误判的止损可能比亏钱更贵。

**Q：数据会上传到外部吗？**
不会。所有数据在你们自己的服务器上。只有接了大模型时，创意类文本会发送给模型服务商。

**Q：一条评论机器分不出来怎么办？**
标记为「待人工确认」，不计入统计、不生成动作。人工补标注后重跑即可。
